# フレンド・対戦機能：段階的な導入

## 現状

Firebaseプロジェクトが未作成のため、オンライン機能はまだ接続・検証できません。
`firebase-account.html` の認証とパスワードマネージャー支援はFirebase設定後に利用可能です。
フレンドコードはFirebase UIDとは別のランダム12桁文字列にし、実名・メールアドレスを含めません。
既存の端末専用IDはFirebase本人確認に使えません。ログイン済みFirebaseアカウントにのみコードを発行します。
旧アカウントの利用者は、右上から自分で発行する導線を提供します。

## フレンドシステムの要件

- コード発行はユーザー操作で実行。発行済みコードは再表示し、繰り返し作らない。サーバー側でコードの一意性を検証する。
- コード入力→承認待ち→承認または拒否→フレンド成立。フレンド解消、申請取消、ブロック、通報、非公開設定も提供。
- お互いの称号・選択したプロフィール情報だけ閲覧できる。メールアドレスやプレイ履歴の生データを開示しない。
- フレンドコードを知っているだけで相手の全プロフィールが見えないようにする。
- 児童向けに自由チャット、実名・位置情報共有、知らない人との自動マッチングを初期導入しない。

## 対戦仕様（実装前の安全要件）

- フレンド同士が対戦招待→承認→同じ課題・タイムリミットでスタート。
- 一つの文章を完成するごとに、相手の未確定文字のうち最大3文字を赤くする。既に赤い文字を重複して数えない。
- 妨害効果はサーバーが検証して一度だけ適用する。遅延・再送で二重に適用しない。
- 勝敗はサーバー検証後の完成度で判定し、同点時はミス数→タイムの順。
- ブラウザから「完成度100%」「相手を妨害」等を直接Firestoreに書いて勝利できないようにする。
- Cloud Functionsなど信頼できる実行環境が必要。課金プランと費用上限を確認してからデプロイする。
- 対戦途中の切断・再接続・不正入力・連打を含むサーバーテストを行う。

## 追加で検討する遊び

フレンドの称号展示、週間協力料理、友達との非同期ベストスコア挑戦、スタンプでの応援、協力で食材を集めるイベント、称号図鑑。勝敗ばかりにならず毎日練習できるよう、個人の継続記録や自己ベストも評価する。

## 注意

`firestore.rules` を更新してもFirebase Consoleには自動反映されません。実際の発行・申請・承認を有効にする前にRules Emulatorで権限・コードの存在漏洩・連続申請の対策を検証してください。
